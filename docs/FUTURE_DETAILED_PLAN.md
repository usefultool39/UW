## 1. 最终目标

《边境回声》要做成一个可沉浸游玩的单人 AI RPG，而不是剧情点击 Demo、AI 聊天室或开发调试界面。

玩家以露茵村见习记录员身份进入边境世界，在日常生活、训练、读书、巡查、同伴关系和村庄传言中，逐步走向北境静默线事件。世界事实由后端规则和剧情配置维护，AI 负责 NPC 表达、反思、记忆候选和主动意图。

长期目标分三层：

1. **可试玩纵切片**：20-60 分钟，高质量完成 Day 1 到 Day 3，并有第一月继续玩的钩子。
2. **第一月章节**：30 天内容路线，把边界事件扩展成巡查、村务、同伴誓约和北门前夜。
3. **前传篇章**：从露茵村日常推进到外部执行者降临，把审判前夜作为第一大章强钩子。

## 4. 阶段二：视觉与美术升级

目标：第一眼像温暖、清晰、可探索的幻想村庄 RPG，而不是网页工具面板。

美术方向：

- 采用细颗粒 2D 俯视 / 高清像素混合风格。
- 地图继续由后端权威网格控制可走性，前端表现层读同一份地图/tileset manifest。
- 不急着转完整 2.5D 等距，避免遮挡、点击映射和路径视觉偏移立刻扩散。

第一批资产：

- 地表：草地、泥路、石路、水岸、森林边缘、障碍。
- 地标：书库、小屋、古誓树、北境边门、村道广场。
- 角色：玩家、爱丽丝、悠吉欧、赛尔卡、加雷特、罗温 idle/walk 四方向基础动画。
- 世界标记：线索光点、入口提示、不可达反馈、目标方向箭头。
- 音效：点击、脚步、雨、水、炉火、异常静默、结算提示。

验收标准：

- 关掉 UI 后，单看地图也能分辨家、书库、广场、古誓树、北门。
- NPC 不站在水上、树上、锁区里。
- UI 不遮挡地图主体，移动端面板可以收起或滑出。
- 玩家移动时不再像静态 token 滑动。

## 5. 阶段三：第一月内容扩展

目标：把 Day 1-3 的边界事件扩展成 30 天可玩路线。

第一月结构以 `data/story/month_01_plan.json` 为准：

- 第 1 周：线索与信任，完成 Day 1-3 边界事件和 Day 4-6 事后复盘。
- 第 2 周：巡查与村内信任，完成北门巡查演练和村务信任。
- 第 3 周：同伴誓约与静默线，完成静默线演练和远征分工。
- 第 4 周：第一次远征准备，完成远征包、北门前夜和第二月路线选择。

需要补齐：

- 每个里程碑至少 1 个主事件、1 个场景活动、1 个 NPC 主动意图。
- 每周至少 1 个关系分歧：秩序优先、调查优先、隐瞒补救。
- 每条 Day 3 结局路线都要影响第一月文案、可选项和 NPC 态度。
- 结算循环展示：谁记住了什么、谁更信任你、谁产生不安、明天有什么目标。

## 6. 阶段四：NPC 智能体系统

目标：NPC 不只是按固定日程站位和聊天，而是能形成目标、行动、记忆和社会影响。

建议新增 `backend/app/agent_loop.py`，但必须保持后端权威事实不被 LLM 直接改写。

智能体循环：

1. 感知：当前时间、位置、玩家行为、可见 NPC、重要 flags、最近事件。
2. 记忆检索：事件记忆、语义记忆、关系记忆、承诺、误会、紧张点、秘密。
3. 目标选择：今日目标、长期目标、关系目标、风险规避。
4. 计划：选择移动、对话、观察、记录、上报、隐瞒、等待。
5. 规则校验：后端确认行动是否合法、是否改变世界事实。
6. 行动输出：写入 NPC intent、日程摘要、对话上下文或记忆候选。
7. 反思：低频生成，不每 tick 调用 LLM。

分层策略：

- 核心 NPC：爱丽丝、悠吉欧。允许更细的记忆和主动意图。
- 重要 NPC：赛尔卡、加雷特、罗温。按里程碑触发目标和关系变化。
- 背景 NPC：只做日程、传言和短摘要，避免成本失控。

## 7. 阶段五：村庄社会扩展

目标：露茵村要像一个社会，而不是只有两个同伴等待玩家点击。

角色职责：

- 爱丽丝：核心羁绊、规则压力、照顾与质疑。
- 悠吉欧：训练、古誓树、边界异常的第一见证。
- 赛尔卡：疗愈、书库侧线、受伤和情绪观察。
- 加雷特：北门巡守、风险提醒、巡查流程。
- 罗温：村务、律令解释、上报压力、村内稳定。

系统补齐：

- 村务板：巡查、食物、训练、书库记录、北门异常。
- 传言系统：玩家行为会被看见、误解、传播或压下。
- 村内信任：村民对玩家的谨慎、认可、怀疑和依赖。
- 离屏摘要：玩家不在身边时，NPC 也会按日程行动并生成简短结果。

## 8. 阶段六：剧情主线完善

第一大章建议停在“外部执行者降临并宣判”的强钩子，不要过早进入后续大地图。

五幕结构：

1. 日常可信：读书、训练、吃饭、帮忙、闲聊建立关系。
2. 异常出现：鸟声消失、风声断开、刻印术短暂失效、旧记录矛盾。
3. 三人调查：安全绳、记录本、刻印标记、补给、路线选择成型。
4. 洞窟或北门事件：在救人、守规则、记录事实、保护同伴之间选择。
5. 审判前夜：村内压力、外部权力、同伴承诺和玩家记录共同推向宣判节点。

每个主线事件都要有：

- 触发条件。
- 场景和参与 NPC。
- 玩家选择。
- 关系、记忆、flags、后续路线影响。
- 失败或未完成时的兜底提示。

## 9. 阶段七：内容工具与调试器

目标：让多 NPC、多事件、多 flags 可维护。

必须工具：

- 世界观察器：当前时间、flags、active events、NPC 位置、NPC 当前目标。
- NPC 调试面板：记忆、关系、计划、最近决策理由、下一步行动。
- 事件时间线回放：查看玩家选择如何影响 Day 2、Day 3 和第一月路线。
- 内容校验扩展：事件 id、flags、participants、POI 可达性、NPC schedule、关系 key、记忆写入。
- 配置编辑辅助：新增 NPC、新增事件、新增场景活动后能快速验证。

工具原则：

- 调试器只在 `?dev=1` 或开发模式显示。
- 普通玩家界面不能出现 JSON、内部 id 和测试按钮。
- 校验失败要指出具体文件、字段和建议修复方式。
