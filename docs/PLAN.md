## 2. 当前执行顺序

只按以下顺序推进；前一阶段没有形成证据，不批量进入下一阶段。

### A. 玩法优化第一阶段（0.6.0 P0，已完成基础闭环）

**目标**：让玩家"想再多玩一天"，在主线框架内填充日常玩法。

1. **已完成｜关系系统可视化**：`BondPanel` 三维关系雷达图（好感/信任/紧张）与结果面板前后数值变化动画。
2. **已完成｜西侧田野采集系统**：每日采药、天气差异产物、三块一次性石碑碎片与收集完成 flag。
3. **已完成｜训练节奏游戏**：五阶段逐步变速、三档判定、连击/断连、阶段进度和结果反馈；保留原有完成 payload 合同。
4. **已完成｜公告柱任务**：村道广场每日三选一小任务，产出关系点或材料。
5. **已完成｜库存基础**：活动可安全结算物品增减，并兼容旧存档。

**完成证据**：后端 275 项测试、前端 45 项单测、Playwright 4 项 E2E、质量门和内容校验通过。主线地点的普通日常入口已让位于 N01-N10；日结算闸在休息按钮上显示真实缺口；烹饪/钓鱼/书库性能伪造回归已覆盖。

### B. 素材候选验收与返工

严格按 `docs/art/ASSET_TASKS.md` 的 T01-T04 执行；每个任务先交一组样张，形成机器检查、人工看图和桌面/移动证据后再扩展。

1. T01：修正当前地图的水印残留、住宅重复和山体层级；通过后才制作正式分层。
2. T02：已准备 candidate-only matte 清理轮（36/36 锚点 alpha 通过机器检查）；仍需人工检查帧间连续性、边缘误伤、角色识别和权利说明，未进入 runtime。
3. T03：基于当前黑白构图制作桌面与移动上色版。
4. T04：修正 `VIS-VFX-001` 的透明度、背景和静默线语义。

**完成证据**：真实游戏截图、素材台账、人工结论和可回滚 runtime 映射。

### C. 玩法优化第二阶段（0.6.0 P1，基础闭环已完成）

**目标**：让采集产物真正进入物品栏、制作和恢复循环，同时继续扩展可重玩的日常活动。

1. **已完成｜物品栏与消耗品系统**：8 格槽位、材料/消耗品/关键道具分类；`use_item` 后端原子校验、资源恢复、条件拒绝和旧存档兼容。
2. **已完成接线｜钓鱼小游戏**（南湖旧渡）：抛竿/咬钩/提竿 QTE、普通/稀有鱼、每日限制和库存产出；生产 gate 仍按 `chapter_03` 锁定。
3. **已完成｜烹饪小游戏**（家中炉火）：切菜节奏 + 火候控制，普通/完美产出草药汤或干粮，并消耗材料。
4. **已完成｜读书推理链**：现象 -> 规则 -> 结论三步顺序；错误选择只在本地反馈，完整链条才提交原有活动结算。
5. **已完成｜巡查道具组合**：出发前选择最多两件合法道具，服务端按库存和组合规则重新验证，改变资源风险和边境标记收益。
6. **已完成基础闭环｜记忆图鉴/成就面板**：服务端只读聚合主线、碎片、活动记录、NPC 记忆和关系里程碑，未解锁内容显示解锁条件。

**当前证据**：后端 275 项测试、前端 45 项单测、Playwright 4 项 E2E、质量门和内容校验通过。巡查与图鉴的真实新玩家截图/盲测证据仍待补齐。

## 5. 计划变更规则

- 新任务必须说明它解决哪个 P0/P1 问题、依赖什么、如何验收。
- 没有进入当前执行顺序的想法，只能放入 P1/P2/P3，不新建方案文件。
- 自动测试通过不等于素材或真人体验通过。
- 候选素材存在不等于完成；只有进入 runtime 并通过真实界面验收才可标记完成。
- 每完成一个阶段，只更新本文件中的事实和证据，不复制新版本。
- **0.6.0 新增**：玩法系统的具体设计以 `docs/MASTER_GUIDE.md` 和 `docs/GAMEPLAY_DESIGN.md` 为唯一事实源；本文件只记录优先级和执行顺序。
