## 2. 当前执行顺序

只按以下顺序推进；前一阶段没有形成证据，不批量进入下一阶段。

### A. 代表性画面闭环

1. 从现有场景插图中选择一张，接入事件面板。
2. 在 1440×900 和 390×844 验证文字安全区、人物站位和裁切。
3. 制作一张代表性村庄地图切片，验证地标、碰撞、遮挡和角色比例。
4. 制作三位核心角色统一风格样张，只验收 idle、四向 walk 和一个角色专属互动。
5. 重做抓捕终点构图，先审故事事实和人物关系，再做精修。

**完成证据**：真实游戏截图、素材台账、人工结论和可回滚 runtime 映射。

### B. 声音与反馈闭环

1. 审核现有 SFX，每个文件补来源、用途、响度和 one-shot/loop 判定。
2. 补最小声音集合：确认、取消、失败、线索、关系变化、脚步、翻书、门、抓捕静默。
3. 验证移动端自动播放限制、音量设置、淡入淡出和无声音时的文字反馈。

**完成证据**：试听记录、测量数据、游戏内录屏或截图说明、manifest 状态。

### C. 连续体验复验

1. 从全新 run 连续完成 N01–N10。
2. 验证至少三次跨节点关系/记忆回响。
3. 验证 N10 后不能错误推进到未规划章节。
4. 复验存档导入导出、失败恢复和 scripted 离线模式。
5. 运行 `./scripts/quality.sh` 和 `./scripts/release.sh`。

**完成证据**：自动化输出、全新 run 日志和终点截图。

### D. 真人盲测与发布判断

1. 招募三名未参与开发的玩家。
2. 不口头教学，记录首次互动时间、卡点、完成率和剧情理解。
3. 只修复重复出现或阻塞通关的问题，不因单一偏好扩大范围。
4. 完成 IP/素材权利评估。
5. 决定内部保留、授权发布或原创化改写。

**完成证据**：3/3 盲测记录、问题归类、修复结果和明确的权利结论。

## 3. 优先级

### P0：当前版本必须完成

- 代表性地图切片与核心地标。
- 三位核心角色统一动作基线。
- 抓捕终点关键图。
- SFX 元数据与最小声音集合。
- N01–N10 连续回归。
- 3 名陌生玩家盲测。
- 权利评估或原创化决策。

### P1：不阻塞内容闭环，但应在发布前处理

- Phaser chunk 按测量结果分包。
- 焦点态、非颜色提示、字体和触控目标复查。
- 减少动态、镜头震动和音量辅助选项。
- 地图/图集/锚点/碰撞自动校验工具。
- 存档 schema 的长期迁移说明与更多兼容样本。

### P2：当前版本之后再评估

- 独立战斗原型。
- 更多可重复生活活动、天气和关系回访。
- 新地图、成长、装备和敌人。
- 爱丽丝被带走后的章节。

## 4. 冻结项

以下事项不得作为当前阻塞项或另起规划：

- 旧见习记录员路线。
- Day/月度内容继续扩写。
- Cocos 迁移、全 3D、联网多人。
- 全角色、全地图、全配音批量生产。
- 无边界 Agent Loop。
- 未经原型验收直接接入完整战斗。

## 5. 计划变更规则

- 新任务必须说明它解决哪个 P0 问题、依赖什么、如何验收。
- 没有进入当前执行顺序的想法，只能放入 P1/P2，不新建方案文件。
- 自动测试通过不等于素材或真人体验通过。
- 候选素材存在不等于完成；只有进入 runtime 并通过真实界面验收才可标记完成。
- 每完成一个阶段，只更新本文件中的事实和证据，不复制新版本。
