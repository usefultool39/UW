### 状态含义

| 状态 | 含义 | 处理规则 |
|---|---|---|
| ✅ 可用 | 内容和技术规格满足当前阶段 | 可进入原型或 runtime；仍需记录接入验证 |
| ⚠️ 适配后可用 | 内容方向成立，但还缺 ID、尺寸、格式、授权或接入适配 | 不直接标成 approved；完成适配和验证后再升级 |
| 🔴 重做 | 水印、IP风险、实际格式/尺寸/透明度错误或视觉方向不成立 | 退回，不进入 runtime；保留旧版作为审计证据 |
| ⏸ 暂缓 | 依赖未满足、当前阶段不需要或尚无真实试玩证据 | 保持 requested/deferred，不假装完成 |

### 重要规则

1. **“视觉上好看”不等于“可以用”**：必须同时满足内容、技术、权利、接入和试玩证据。
2. **sidecar、MANIFEST 和实际文件不一致时，以实际文件检查结果为准，并退回修正。**
3. **没有进入 runtime 的素材，不算已经改善真实游戏体验。**
4. **自动化测试通过不等于新玩家能看懂；易上手必须由陌生玩家盲测证明。**
5. **后端仍是世界状态、关系、奖励、flag、剧情闸和永久记忆的唯一权威。**
6. **scripted 是离线产品基线；hybrid/agent 只能改变表达和意图建议，必须可回退。**

## 2. 当前冻结方案

### 2.1 视觉层级：A → B → C，不是三套平行主题

- **A / 北境秩序**：村庄、开场、第一次移动、安全感、清晰目标。
- **B / 旧书库律法**：阅读、记录、档案、关系复盘、文字权威。
- **C / 静默线边界**：异常、边界调查、声音缺失、悬念升级；不作为首屏主色。

### 2.2 当前玩法短循环

> 看到线索 → 选择行动 → 预览代价/收益 → 执行 → 看到关系/记忆/资源回响 → 得到下一条目标。

任何新增素材都必须回答：它强化了短循环中的哪一环？如果不能强化当前环节，不进入 Day 1–3 P0。

### 2.3 当前接入顺序

1. UI 图标：HUD、任务卡、行动预览、结果面板。
2. BGM / ambience v002：村庄、书库、边界三种状态。
3. 修复后的关键图：开场、书库、边界结果/状态，不替换地图底图。
4. 修复后的 256 肖像：对话、结果、关系反馈。
5. Lore / Bark adapter：接入书库和地点短句池。
6. 3 名陌生玩家 Day 1 盲测。
7. 试玩通过后再做地图、sprite、VFX、SFX、AI corpus 和宣传素材。

### 3.1 已确认的硬规格问题

#### 关键图 v002

- 文件名为 `.png`，实际是 JPEG。
- 实际尺寸为桌面 `1376×768`、移动 `768×1376`。
- sidecar/manifest 写的是桌面 `2560×1440`、移动 `1440×1920`。
- 结论：保留构图，重新导出并同步登记信息。

#### 肖像 v002 master

- 文件名为 `.png`，实际是 JPEG 3 通道。
- 没有真实 alpha，棋盘格背景被烘进图像。
- sidecar 写的是 `1024×1024 RGBA 透明背景`。
- 结论：保留角色方向，重新输出透明 PNG。

#### 音频元数据

- BGM A/B 和 ambience v002 的媒体规格、时长和响度基本满足内测要求。
- `materials/inbox/audio/audio.meta.json` 仍未登记 ambience v002。
- 结论：补版本化 runtime manifest 后再接入。

## 4. 当前项目宏观审查

### 4.1 优势

- **可玩性**：行动代价、收益预览、结果反馈和关系回响已形成闭环。
- **吸引力**：稳定日常、记录权威、静默线异常、关系后果的悬念结构成立。
- **易上手**：单一主 CTA、路线层级、NPC 入口去重方向正确。
- **工程**：FastAPI 权威状态、scripted 离线基线、hybrid/agent 回退边界清楚。
- **扩展性**：活动 registry、事件结果、永久记忆和 NPC runtime envelope 已有兼容结构。

### 4.2 当前风险

1. 没有真实陌生玩家盲测，不能证明第一次玩家能独立完成 Day 1。
2. 新视觉和音频素材尚未进入 runtime，真实体验仍主要由旧 token、旧底图和程序化音频组成。
3. manifest 的 `approved-candidate` 不能完全信任，已发现 sidecar 与实物不一致。
4. Lore/Bark 内容质量不错，但没有直接的运行时事件/状态 ID。
5. 当前代码和文档有角色旧名漂移，需要统一显示名、内部 ID 和历史别名。
6. README 的非商业二次创作定位与 v002 “原创/去 IP 化”表述需要明确双轨规则。
