# 产品简述：边境回声 · Underworld 分支篇

- **状态**：Current
- **最后更新**：2026-08-03

## 一句话愿景

一款容易上手、以 NPC 记忆与关系后果为核心的单人叙事 RPG：玩家先体验安静可信的卢利特村生活，再逐步察觉北方边境和世界规则中的不安。

## 定位

- 背景参考 Underworld 氛围、公开术语和部分角色，采用分支时间线。
- 玩家是原创“见习记录员”，不是复刻原作主角路线。
- 首个交付是 30–45 分钟 Day 1–3 纵切片。
- NPC 不只是任务入口：他们记住选择、承诺和冲突，并在后续关系与事件中体现。
- 无 API 时完整可玩；未来按 NPC 灰度切换 Hybrid / Agent。

## 体验支柱

1. **容易上手**：一分钟内知道身份、地点、主目标和第一步。
2. **行动有判断**：时间、体力、生命、神圣力、关系和线索的收益/代价可理解。
3. **后果可感知**：重要选择当下反馈，之后至少有一次可见回响。
4. **安静逐渐失衡**：日常建立安全感，异常持续累积不安。
5. **离线完整、智能可插拔**：脚本是产品底线，模型是增强层。

## 核心循环

```text
查看今日目标 → 移动与观察 → 活动/对话/训练/巡查
→ 支付时间和资源 → 获得线索/关系/进展
→ NPC 记住结果 → 休息进入新日 → 状态解锁新事件
```

## 参考作品如何使用

只提炼机制，不复制具体关卡、文本、美术或数值：

- 《元气骑士》：短反馈、清晰操作、快速重试。
- 《魔塔》：行动前能预估资源代价。
- 日程型生活叙事：地点、时间、关系共同决定内容。
- 悬疑叙事：先建立稳定规则，再让小异常升级。

## 非目标

- 当前不做 MMO、开放世界、联网多人和无限生成剧情。
- 不追求 100% 复刻原作剧情或台词。
- 不把 Cocos 迁移、全 3D 或大规模美术作为阻塞项。
- 不允许模型直接改写权威世界状态、奖励或剧情闸。

## 成功信号

- 新玩家无需讲解完成 Day 1。
- 30–45 分钟内体验资源决策、关系后果和异常升级。
- 离线模式完成纵切片；API 配置失败不影响存档可玩性。
- 关键流程自动回归，新增内容不靠人工猜测是否破坏旧剧情。

## Underworld 参考基线（2026-08-05）

本项目的背景和人物关系参考《刀剑神域 Alicization / Underworld》早期的人界与露茵村语境，但本项目采用分支时间线和原创玩家身份，不直接复述原作台词、章节文本、镜头或美术。

### 作为游戏设计基线的原作要素

- **露茵村日常**：小村庄、固定劳作、熟人关系和明确的社会规则，适合做可反复回访的生活舞台。
- **天职与日程**：尤吉欧承担砍伐巨树的天职；这类固定劳作适合转化为每日活动、技能练习和关系场景。
- **古誓树/巨树意象**：日常劳动表面平静，但与世界规则、边界和异常形成对照。
- **禁忌目録与制度压力**：玩家的选择不只是“善恶”，还会受到村规、教会规则和他人安全判断的约束。
- **爱丽丝与尤吉欧的不同立场**：爱丽丝更偏探索、判断和突破；尤吉欧更偏谨慎、责任和对规则的担忧。游戏应让玩家在两种立场之间做选择，而不是把关系简化为数值加减。
- **从村庄到远方**：原作的重要转折不是无缘无故换地图，而是由一次越界/异常事件推动角色离开日常，进入更大的世界。
- **记忆与身份**：Underworld 的核心冲突涉及记忆、身份、规则和“一个人能否保留自己的选择”。本项目的 NPC 记忆系统应服务于这些主题。

### 本项目的时间锚点

当前版本默认采用“露茵村早期生活的分支时间线”作为第一章，不直接把 War of Underworld 的战场、战后状态或后期角色身份混入 Day 1–3。后续如果要制作 War of Underworld 时代内容，应另设章节和时间线，避免与童年露茵村内容发生设定冲突。

### 角色功能翻译

| 原作参考 | 本项目中的游戏功能 |
|---|---|
| 爱丽丝 | 探索、记录完整性、风险判断、关系压力与突破规则的冲动 |
| 尤吉欧 | 日常劳作、训练、撤退判断、承诺、对规则和责任的顾虑 |
| 赛尔卡 | 家庭/疗愈/情绪观察，承担生活感和关系缓冲 |
| 露茵村 | 可重复回访的生活地图，而不是一次性剧情背景 |
| 禁忌目録/教会规则 | 事件闸、选择代价、村庄共识和越界风险 |
| 北境/尽头山脉方向 | 从日常生活逐步过渡到冒险调查的主线出口 |

### 原作参考边界

可以提炼世界结构、情绪主题、人物关系功能和事件节奏；不得直接复制原作长段落、官方角色定妆、动画截图、游戏 UI、原作音乐或独特镜头构图。若未来公开发布或商业化，应将角色名、地名、术式名和世界设定整体迁移为原创版本，而不是只替换素材。
