## 问题

- 三张 sheet 是程序化几何人偶，轮廓、服装、头发、朝向和动作差异过弱；缩放到实际显示高度后无法达到正式角色识别与情感表达标准。
- walk/interact 主要是轻微像素位移，视觉上接近重复帧；不满足“静态立绘不能冒充角色动作”的产品要求。
- JSON 使用 `frame_cell_px`、通用动画摘要和扁平 `frames`，与 gate 所需顶层 `frame_width`/`frame_height` 和 `down_idle` 等 12 组动画结构不一致。
- 每帧缺 gate 可直接解析的 `source` 与 `[x,y,width,height] rect` 组合。

## v004 修改要求

- 使用真正的原创 2D Sprite 制作流程重做三名儿童角色，统一 64x96 或 96x128 cell；在 44-52px 显示高度仍能区分桐人、爱丽丝、尤吉欧。
- 每方向 idle 2、walk 6、interact 4 帧必须存在可观察的身体/脚步/手臂变化，统一脚底锚点和碰撞 footprint。
- 输出真实 8-bit RGBA，背景透明且角色像素可见；禁止棋盘格、场景、文字、烘焙阴影和单姿势复制。
- metadata 使用 `frame_width`、`frame_height`、`animations.down_idle` 至 `animations.up_interact`；每帧提供 source 与 rect。
- 不得删除或覆盖 v003；新文件统一 v004。

## 验收标准

- 三个 v004 包分别通过 alpha、透明像素、frame count、rect、边界和 distinctness gate。
- 4 个方向和 3 类动作在 100% 与游戏内缩放下均可辨认，脚底不漂移。
- 项目负责人完成角色比例、地图光照、移动与交互触发截图 QA 后，才允许进入 runtime。
